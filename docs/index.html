一条真实案例

一份办事文档，从乱材料到对得上的稿。

不讲抽象能力。只走一遍家庭养老保险提档补差案例里实际发生过的事。

01

你给它什么

缴费记录、电话核实笔记、政策摘录——材料散，口径不一，有的只有电话、没有网页链接。

输入：真实材料，不是「帮我写一篇」四个字。

02

它先问清楚谁在用

读者是不懂社保的家属；目的是 12 月去窗口前定档次、办业务，并留一份以后能查的记录。

动作：先定读者和目的，再动笔。

03

它怎么改句子

一句里挤了四个时间点，拆开；把「已确认」写成「恩阳区城乡局已确认」。年份、年限、条件一个没丢。

动作：润色时补出处，不改事实。

04

它怎么拦数字错

补差总额一度写成 39,750，正确应为 50,050。后来要求合计独立复算；终稿对账等式 46,400 + 4,000 × 3 = 58,400 两边咬合。

动作：算术对账；这次错误直接催生了 check_fidelity.py。

05

它交什么

摘要 → 已确认事实 → 核算与方案 → 时间线 → 行动清单 → 依据与术语。电话答复标成「电话，无链接」，不伪装成网页出处。

交付：家属能照着办的文档结构 + 出处边界写清楚。

06

它不做什么

不编造没有的链接；不把「约」写成确定数；检查脚本只报告，不自动覆盖原文。

边界：脚本过关 ≠ 业务事实已经核定。

完整摘录、目录与历史检查结果 → 家庭办事文档案例页

差别

和普通润色差在哪。

普通润色 / 去 AI 味这个 Skill
句子更顺顺，且数字、出处还在
直接改文件可以只检查；改了会列清单
口头说「已核实」电话就写「电话，无链接」
「可能」常被写死「约 / 可能 / 待核实」原样保留
靠感觉判断好不好有脚本报告；脚本不改你的文件

两种用法

  • 文档模式（默认）：办事指南、方案、报告、邮件、汇报。先定读者，再装进结构，出成稿与检查结果。
  • 文章模式：公众号 / 头条正文，或去 AI 味。先诊断再改；不编第一人称，不承诺绕过检测。

脚本做什么

六个纯 Python 标准库工具：锯末词、句长、节奏、表格标题、算术对账、改前改后差异。advisory 只提醒；表格结构和算术不一致可以阻断。全部只报告，不自动改写。

# 案例终稿检查摘要（历史记录）
check_fidelity 补差曾写成 39,750 → 复算后对上
check_fidelity 46,400 + 4,000 × 3 = 58,400 ✓
# 脚本不替代来源核实或人工审读
