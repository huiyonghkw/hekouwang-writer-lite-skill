检查档报告与边界

检查请求不等于改写授权。

检查档的输出固定包含四列：位置、原句、问题、建议，另加一列验证状态。位置要能让人回到原文，原句照抄不改，问题描述具体到“哪个词导致什么歧义”，建议只给方向，不直接生成替代段落。验证状态说明这条结论来自机器检查、人工判断，还是尚未核实。

为什么要分开？因为发现问题和决定怎么改是两件事。表格合计与分项不一致，可能是分项错，也可能是合计错，还可能两边都引用了过时的来源。检查器只能指出不一致，不能替业务判断哪个数字为准。直接改文件会把一个待核实的问题伪装成已经解决。

检查顺序也有讲究：先看来源是否成立，再看结构是否完整，然后核对数字关系，最后才处理文风。来源错了，句子再顺也没有意义；结构缺了一节，局部润色救不回来。工具分级同样要如实说明：锯末词、句长和节奏属于提醒，命中后进程仍返回 0；表格结构和算术关系属于确定性检查，可以返回 1 阻断。

报告交付后，由用户决定改不改、改哪一处。若用户随后授权修订，才进入修订模式，并保留原句与改动清单。这个分界让“检查过”和“改过了”不会混成同一句话。
